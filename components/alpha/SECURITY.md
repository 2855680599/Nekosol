# SECURITY

本文件说明如何上报漏洞、本发布版本对「不包含什么」的保证，以及**一个尚未解除的真实发布门禁**。

---

## 1. 如何上报漏洞

| 阶段 | 方式 |
| --- | --- |
| 公开仓库建立后 | 请在公开仓库使用 **GitHub Security Advisory**（`Security` → `Report a vulnerability`）私密上报，不要开 public issue |
| 当前公开框架 | 请按仓库根目录 [SECURITY.md](../../SECURITY.md) 使用实际可用的私密反馈渠道。 |

上报时请尽量给出：受影响文件与行号、复现步骤、期望行为与实际行为、以及你判定为安全影响的原因。我们会先确认收到，再给出评估结论（不影响 / 需要修复 / 需要公告）。

**关于凭据：请勿在 issue、讨论区或任何公开渠道粘贴任何密钥值。** 本文档也从不打印任何凭据值。

## 2. 本发布版本的保证

### 2.1 仓库内容保证

| 保证 | 状态 |
| --- | --- |
| 不含任何凭据、密钥、令牌 | ✅ 本发布树内无凭据 |
| 不含个人数据（真实姓名、账号、聊天标识、健康数据） | ✅（唯一的例外见 §2.4：少量**开发机本地路径字串**，不含任何内容数据） |
| 不含真实消息内容 | ✅ 无真实会话/消息日志 |
| 不含真实数据库 | ✅ 无生产 `.env` 快照、无 `*.sqlite3` / `*.db` 生产库、无 pid/lock 快照 |
| 默认不发送 | ✅ 四个 kill switch 全部默认 false；Contact 链的唯一 transport 是树内 recording 假实现 |
| 主动外发在构造上不可达 | ✅ 隔离演示不绑定真实 Telegram transport（boundary 内任何 socket 调用都会被拒绝） |

### 2.2 运行期保证

* `chiyo demo core` / `chiyo demo contact` 在隔离数据目录中运行，**不需要**连接任何 VPS、私有数据库、Telegram token，也**不需要**恢复任何个人状态。
* 生产隔离机制由所有者模块自身强制：在 `/root/.hermes*` 之类的生产 home 下，路径检查直接拒绝，ActionStore 会抛 `Production cutover is forbidden in AR-0`。也就是说「接上真实 owner 但把闸门锁死」是**由构造保证**的，不是靠演示脚本自觉。
* 本版本未改动任何生产 kill switch 的取值。

### 2.3 一处有意的脱敏

本发布树中保留了一个**被有意脱敏的生产目的地址常量**（标注为未使用，且伴随 `PRODUCTION_COUNTERPARTY_USED = False`）。它被保留是为了让「真实地址从未被使用」这件事可被静态复核；**其值已被抹除**，不构成可用的目的地址或凭据。

### 2.4 开发机本地路径候选（导出时已清除）

清点阶段发现 `chiyo/contact/` 下 **4 个模块共 24 处**曾保留**开发机本地路径候选**（Windows 用户目录形态的
路径字串，以及上一轮会话 scratch 目录下的只读抓取路径），原本作为只读的查找回退。

**处置：导出时已全部清除。** 复制进发布树的模块不再包含任何机器相关路径；核心逻辑未受影响
（这些候选只是解析顺序里的回退项，去掉后冷启动与演示链路均照常通过）。清除记录见发布树
`SANITISATION.md`。

**验证方式**：验收脚本 `tests/acceptance/e_safety.py` 对发布树做模式化扫描，当前结果
`developer_username: []`、`personal_windows_path: []`、`personal_posix_capture: []`、
`pi_desktop_scratch: []`（零命中）。同一扫描还覆盖 Telegram bot token、`sk-` 形态密钥、私钥块、
GitHub/Slack token、个人邮箱、真实 chat id 与 VPS 地址，均为零命中；其唯一披露项是扫描器
自身的模式字面量（`tests/acceptance/e_safety.py`），属预期自引用。

保留本节而不是删掉的理由：这条历史痕迹真实存在过，记录它、并记录它**已经被清除且已被扫描器证明**
比单纯删掉段落更可核验。

## 3. 尚未解除的发布门禁（必读）

### 3.1 事项：`SEC-CONTACT-LEGACY-CREDENTIAL`

一次先行审计（工作项编号 `SEC-CONTACT-LEGACY-CREDENTIAL`）在本发布版本**所筛取的 legacy 源码树**中发现了真实凭据材料。发现内容按位置描述如下（**不列出任何值**）：

| 类型 | 位置（legacy 树，未随本发布） |
| --- | --- |
| 硬编码 API-key 字面量 | **两个** legacy 脚本：一个把密钥字面量写成环境变量读取的默认回退值，另一个同类写法 |
| Telegram `API_ID` / `API_HASH` | **另一个** legacy 脚本 |
| 生产 `.env` 快照 | 若干 `rollback-*` 目录下的 `.env` / `GATEWAY.env` 快照，以及 pid / lock 文件 |

**这些材料都没有进入本发布树。** 本发布只包含筛选后的 core + contact 模块；对这些模块的扫描结果干净，唯一的例外是上面第 2.3 节那一个**已被有意脱敏**的生产目的地址常量（从未被使用）。

### 3.2 未完成的部分

| 项 | 状态 |
| --- | --- |
| 上游凭据是否已被吊销 | **未确认** |
| 上游凭据是否已轮换 | **未确认** |
| 因此：公开发布 | **受门禁限制（gated）** |

在凭据的吊销 / 轮换得到确认之前，**本发布不得公开发布**。解除门禁需要两条证据：受影响的凭据值（或对应令牌）已被吊销或轮换，并保留可复核的记录。

维护者请勿在修复过程中把任何值写进本仓库、提交信息或 issue。

## 4. 上报范围之外

* 本仓库**不包含**生产部署、生产数据库、生产 transport 绑定；针对这些环境的问题请不要用本仓库的 Security Advisory。
* 可选的真实 Telegram 被动聊天插件为第三方组件，其自身漏洞请按其上游项目的方式上报；本包默认不安装、不启用该组件。见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
